# 云沙箱用户场景全景调研

> 文档版本：v1.0 | 最后更新：2026-09-01

---

## 1. 十大核心场景（按使用频率排序）

### 场景 1：AI 代码执行（Code Interpreter）

**场景描述：**
AI Agent（如 ChatGPT、Claude、通义千问）在对话过程中需要执行用户提供的代码片段，获取运行结果后返回给用户。这是云沙箱最高频的使用场景，也是 E2B 的核心设计目标。

**所需沙箱能力：**
- 亚秒级冷启动（用户等待时间 < 2s）
- 多语言运行时（Python、JavaScript、R、Java）
- Jupyter 内核支持（Code Interpreter 协议）
- 标准输出/错误流实时回传
- 图表/图片等富媒体输出支持
- 文件上传/下载（用户上传数据文件）
- 自动超时和资源限制

**典型用户画像：**
AI 产品团队、SaaS 平台开发者、Copilot 类工具开发者

**推荐沙箱模式：** 临时沙箱（Ephemeral）
- 每次对话创建，对话结束销毁
- 单次执行超时：30s ~ 5min
- 无需持久化

**推荐模板：** `code-interpreter-python`、`code-interpreter-multilang`

---

### 场景 2：Vibe Coding / AI 应用生成

**场景描述：**
AI Agent 根据用户自然语言描述，自动生成完整应用代码（前端、后端、全栈），在沙箱中实时编译、运行并预览。典型产品如 Bolt.new、v0.dev、Lovable 等。

**所需沙箱能力：**
- 完整开发环境（Node.js + npm/pnpm/yarn）
- 端口暴露和 HTTP 预览（开发服务器）
- 文件系统读写（项目脚手架生成）
- Shell 命令执行（npm install、build）
- 较长生存时间（用户持续迭代）
- 实时文件监听（watchDir）
- 自定义域名（预览分享）

**典型用户画像：**
AI 应用生成平台、低代码平台、在线 IDE 产品

**推荐沙箱模式：** 持久沙箱（Persistent）
- 跨会话保持，用户可随时回来继续
- 生存时间：1h ~ 24h
- 支持暂停/恢复降低成本

**推荐模板：** `nextjs-developer`、`react-vite`、`vue-developer`

---

### 场景 3：数据分析报表

**场景描述：**
用户上传 CSV/Excel/数据库导出文件，AI Agent 自动进行数据清洗、分析、可视化，生成分析报告和交互式图表。

**所需沙箱能力：**
- 数据科学工具链（pandas、matplotlib、seaborn、plotly）
- 大文件上传支持（100MB+）
- Jupyter 内核（交互式数据探索）
- 图表渲染和导出（PNG、SVG、HTML）
- 临时文件存储（处理中间数据）
- 较大内存（数据处理需要）

**典型用户画像：**
数据分析师、业务运营人员、BI 平台产品团队

**推荐沙箱模式：** 临时沙箱（Ephemeral）
- 按分析任务创建
- 超时：5min ~ 30min
- 结果导出后销毁

**推荐模板：** `data-analysis-python`、`jupyter-full`

---

### 场景 4：CI/CD 测试执行

**场景描述：**
在 CI/CD 流水线中使用沙箱执行单元测试、集成测试，实现测试环境隔离。每次 PR/MR 触发创建独立沙箱运行测试套件。

**所需沙箱能力：**
- 自定义镜像（匹配项目技术栈）
- Shell 命令批量执行
- 退出码和测试报告获取
- 并发创建多个沙箱（并行测试）
- VPC 网络访问（连接测试数据库）
- 环境变量注入（测试配置）
- CLI 自动化支持（JSON 输出）

**典型用户画像：**
DevOps 工程师、QA 团队、平台工程团队

**推荐沙箱模式：** 临时沙箱（Ephemeral）
- 测试完成即销毁
- 超时：5min ~ 30min
- 需要高并发

**推荐模板：** `ci-runner-node`、`ci-runner-python`、`ci-runner-java`

---

### 场景 5：Computer Use / 浏览器自动化

**场景描述：**
AI Agent 控制完整的桌面环境或浏览器，执行 GUI 操作：网页浏览、表单填写、截图分析、自动化测试。Anthropic Computer Use 和 Browser Use 是典型代表。

**所需沙箱能力：**
- 桌面环境（Xfce/LXDE + VNC/noVNC）
- 浏览器（Chrome/Chromium + ChromeDriver）
- 屏幕截图和流式传输
- 鼠标/键盘事件注入
- 较大资源规格（桌面环境资源消耗大）
- 端口暴露（noVNC 预览）
- Playwright/Selenium 支持

**典型用户画像：**
RPA 开发者、AI Agent 框架开发者、自动化测试团队

**推荐沙箱模式：** 临时沙箱（Ephemeral）/ 持久沙箱
- 取决于任务复杂度
- 超时：5min ~ 2h
- 需要较大资源

**推荐模板：** `desktop-sandbox`、`browser-use`、`playwright-sandbox`

---

### 场景 6：开发环境（Cloud Development Environment）

**场景描述：**
为开发者提供远程、标准化的开发环境。类似 GitHub Codespaces、Gitpod 的体验，通过 SSH 或 Web IDE 连接云端沙箱进行开发。

**所需沙箱能力：**
- 完整 Linux 开发环境
- SSH 服务和密钥管理
- Git 集成（clone、commit、push）
- LSP（Language Server Protocol）支持
- 持久化文件系统
- 端口转发（多端口开发服务器）
- 自定义域名（项目预览）
- VPC 网络（访问内部服务）

**典型用户画像：**
开发团队、远程办公团队、教育培训机构

**推荐沙箱模式：** 持久沙箱（Persistent）+ 休眠（Hibernate）
- 长期保持，不使用时休眠
- 生存时间：数天 ~ 数周
- 按需唤醒

**推荐模板：** `dev-env-full`、`dev-env-python`、`dev-env-node`

---

### 场景 7：ML 训练 / 推理

**场景描述：**
在云端沙箱中运行机器学习模型的训练任务或推理服务。需要 GPU 资源，适合中小规模训练和模型部署。

**所需沙箱能力：**
- GPU 支持（NVIDIA T4/A10G/A100）
- CUDA 工具链
- 大容量存储（模型文件、训练数据）
- Volume 持久化（检查点保存）
- 长运行时间支持（训练任务可能数小时）
- 高带宽网络（下载数据集、模型）
- OSS 挂载（大规模数据访问）

**典型用户画像：**
AI 研究员、ML 工程师、数据科学团队

**推荐沙箱模式：** 持久沙箱（Persistent）
- 训练期间持续运行
- 超时：1h ~ 24h
- 支持检查点恢复

**推荐模板：** `ml-pytorch`、`ml-tensorflow`、`ml-jax`

---

### 场景 8：安全分析

**场景描述：**
在隔离沙箱中执行可疑代码、恶意软件分析、漏洞扫描等安全研究任务。核心诉求是强隔离，防止恶意代码逃逸。

**所需沙箱能力：**
- 强隔离（microVM 级别）
- 网络隔离（可选断网模式）
- 行为监控（系统调用、网络请求日志）
- 快照/恢复（分析前保存干净状态）
- 自定义镜像（安全工具链）
- 限制资源（防止资源耗尽攻击）

**典型用户画像：**
安全研究员、SOC 团队、渗透测试工程师

**推荐沙箱模式：** 临时沙箱（Ephemeral）
- 每次分析创建全新沙箱
- 分析完成立即销毁
- 严格资源限制

**推荐模板：** `security-sandbox`、`malware-analysis`

---

### 场景 9：教育在线编程

**场景描述：**
在线编程教育平台为每个学生提供独立的编程环境，支持代码编写、运行、评测。典型产品如 LeetCode、Codecademy 等。

**所需沙箱能力：**
- 多语言支持（Python、Java、C++、Go 等）
- 快速启动（学生无需等待）
- 资源隔离（学生间互不影响）
- 标准输入/输出支持（OJ 评测）
- 预装教学依赖
- 低成本（教育场景对价格敏感）
- 批量创建能力（班级同时上课）

**典型用户画像：**
在线教育平台、高校、编程培训机构

**推荐沙箱模式：** 临时沙箱（Ephemeral）
- 按练习/考试创建
- 超时：10min ~ 1h
- 需要高并发

**推荐模板：** `edu-python`、`edu-java`、`edu-cpp`

---

### 场景 10：API 服务临时部署

**场景描述：**
快速部署一个临时 API 服务用于演示、测试或 Webhook 接收。无需配置域名、证书、负载均衡，沙箱自动提供可访问端点。

**所需沙箱能力：**
- HTTP 端口暴露和公网访问
- 自定义域名（可选）
- HTTPS 支持
- 较长生存时间（演示期间保持可用）
- 环境变量注入（API 密钥等）
- 日志查看

**典型用户画像：**
后端开发者、产品经理（Demo 演示）、Webhook 调试

**推荐沙箱模式：** 持久沙箱（Persistent）
- 部署后保持运行
- 超时：1h ~ 24h
- 支持按需更新

**推荐模板：** `api-python-fastapi`、`api-node-express`

## 2. 沙箱模式与场景映射表

| 场景 | 临时沙箱 | 持久沙箱 | 休眠沙箱 | 推荐资源规格 |
|------|---------|---------|---------|-------------|
| AI 代码执行 | ✅ 首选 | - | - | 0.5C/512M |
| Vibe Coding | - | ✅ 首选 | ✅ 可选 | 2C/4G |
| 数据分析 | ✅ 首选 | - | - | 2C/4G |
| CI/CD 测试 | ✅ 首选 | - | - | 2C/2G |
| Computer Use | ✅ 短任务 | ✅ 长任务 | - | 4C/8G |
| 开发环境 | - | ✅ 首选 | ✅ 首选 | 4C/8G |
| ML 训练/推理 | - | ✅ 首选 | - | GPU + 16G |
| 安全分析 | ✅ 首选 | - | - | 1C/2G |
| 教育编程 | ✅ 首选 | - | - | 0.5C/512M |
| API 临时部署 | - | ✅ 首选 | ✅ 可选 | 1C/1G |

### 模式定义

| 模式 | 说明 | 生存时间 | 计费 |
|------|------|---------|------|
| **临时沙箱（Ephemeral）** | 创建即用，用完即毁 | 秒 ~ 小时 | 执行时长 |
| **持久沙箱（Persistent）** | 跨会话保持，持续运行 | 小时 ~ 天 | 运行时长 |
| **休眠沙箱（Hibernate）** | 不使用时暂停，按需恢复 | 天 ~ 周 | 存储费用（暂停期间） |

## 3. 用户需求缺口分析

### 3.1 当前已满足的需求

| 需求 | 满足方式 |
|------|---------|
| 基础代码执行 | E2B Commands.run() |
| Jupyter 代码执行 | E2B Code Interpreter |
| 文件读写 | E2B Filesystem API |
| 自定义镜像 | E2B Template |
| 沙箱生命周期管理 | E2B Sandbox CRUD |

### 3.2 关键缺口

#### 缺口 1：GPU 计算能力

**现状：** E2B 不支持 GPU，ML 训练/推理场景无法覆盖。
**影响场景：** ML 训练/推理、大模型 Fine-tuning
**建议：** 基于 FC GPU 实例提供 GPU 沙箱选项

#### 缺口 2：持久化与休眠

**现状：** 暂停/恢复需白名单，Volume 不支持。
**影响场景：** 开发环境、Vibe Coding、API 临时部署
**建议：** 提供 AgenticFS Volume 和快照恢复能力

#### 缺口 3：网络隔离与 VPC 集成

**现状：** E2B SDK 不支持 VPC 配置。
**影响场景：** CI/CD 测试（访问内网数据库）、开发环境、安全分析
**建议：** 在统一 SDK 中集成 VPC 配置能力

#### 缺口 4：端口暴露与自定义域名

**现状：** E2B getHost() 提供临时 URL，无自定义域名。
**影响场景：** Vibe Coding 预览、API 临时部署、开发环境
**建议：** SDK 支持端口暴露配置和自定义域名绑定

#### 缺口 5：批量操作与高并发

**现状：** 并发限制 20，无批量创建 API。
**影响场景：** 教育编程（班级同时上课）、CI/CD（并行测试）
**建议：** 提供批量创建 API，支持配额提升

#### 缺口 6：监控与日志

**现状：** Logs API 返回空，Metrics 磁盘为占位值。
**影响场景：** 所有生产场景
**建议：** 集成 SLS 日志和云监控

#### 缺口 7：LSP 与 Git 集成

**现状：** E2B 不支持 LSP 和 Git 集成。
**影响场景：** 开发环境、Vibe Coding
**建议：** 模板中预装 LSP Server，提供 Git 操作辅助 API

#### 缺口 8：安全增强

**现状：** 缺乏网络隔离模式和行为监控。
**影响场景：** 安全分析
**建议：** 提供断网沙箱模式和系统调用审计日志

### 3.3 需求优先级矩阵

| 优先级 | 需求 | 影响场景数 | 实现复杂度 |
|--------|------|-----------|-----------|
| P0 | 持久化与休眠 | 4/10 | 中 |
| P0 | 监控与日志 | 10/10 | 低 |
| P1 | VPC 网络集成 | 3/10 | 中 |
| P1 | 自定义域名 | 3/10 | 低 |
| P1 | 批量操作 | 2/10 | 低 |
| P2 | GPU 计算 | 1/10 | 高 |
| P2 | LSP/Git 集成 | 2/10 | 中 |
| P2 | 安全增强 | 1/10 | 高 |
